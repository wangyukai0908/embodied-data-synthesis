# VLA 与 WAM：离线训练和在线部署

本文补充两类模型在数据链路中的部署边界。WAM 不是一个固定架构，实时性取决于具体实现。

## 概念区别

| 维度 | VLA | WAM |
|---|---|---|
| 主要职责 | 视觉、语言、状态到动作 | 世界表征或视觉动态到动作，也可能先预测未来再解码 |
| 离线训练输入 | 带任务文本和动作的具身轨迹 | 轨迹、视频表征、状态和动作，依实现而定 |
| 在线输出 | action chunk，按控制周期执行 | 直接 action chunk，或世界模型 rollout 后再输出动作 |
| 对本仓数据的关系 | GR00T 是已验证的消费端 | WAM 是参考消费端，尚无本仓端到端证据 |

IDM 的方向不同：它从多帧视觉变化反推伪 action，用于数据生产；VLA/WAM 的动作是推理时要执行的控制输出。

## 离线训练链路

```text
视频 / 状态 / 语言 / 动作 / 时间
        → schema 与 embodiment 对齐
        → DataLoader
        → VLA 或 WAM 训练
        → checkpoint
        → 离线误差和数据质量检查
```

离线训练可以在没有机器人连接的环境中完成，但必须保留动作维度、控制频率、归一化统计量和本体标签。loss 下降只说明优化过程正常，不代表在线控制有效。

## 在线部署链路

```text
当前观测 + 任务语言 + proprioceptive state
        → 本地推理
        → action chunk
        → 动作范围/安全约束
        → 机器人执行
        → 新观测和下一轮推理
```

VLA 通常可以直接采用“观测到 action chunk”的在线接口。WAM 若直接把世界表征解码为动作，也可以采用相同方式；若需要先 rollout 世界模型、比较候选未来再选动作，显存、延迟和工程复杂度会明显增加。

## 必须实测的部署指标

1. 单次推理延迟和端到端控制周期。
2. action chunk 长度、执行比例和 replan 频率。
3. 相机帧率、timestamp 延迟和丢帧处理。
4. 动作维度、坐标系、归一化和范围约束。
5. 异常观测、模型超时和安全停止策略。
6. 仿真 rollout、真机成功率、鲁棒性和跨场景泛化。

## 对本仓案例的解释

- DreamGen → IDM → LeRobot → GR00T 已验证离线数据接入和 20k-step 微调接口。
- Cosmos action-conditioned 已验证“真实动作条件 → 未来视频”的离线推理接口。
- 以上都没有验证在线真机控制收益。
- WAM 目前只能作为接口设计和后续验证对象，不能写成已部署系统。
