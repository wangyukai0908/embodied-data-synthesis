## 使用说明

这是一份面向 PPT 生成的编辑稿，不是连续论文。每个 `Slide` 对应一页 PPT；每页只保留一个主张，并列出要点、页面类型和素材位。四个 Part 是汇报的一级结构，后续生成 PPT 时按 Part 顺序排版。

### 参考 PPT 借鉴的编排原则（不作为页面内容）

- 先问题，后架构，再流程，最后结果。
- 一页只回答一个问题，标题直接说结论。
- 图用于解释对象：优先真实机器人照片、数据样例、架构图、流程图和结果表。
- 第一次出现专业术语时，同时说明它在链路中负责什么。
- 结果页同时写“证明了什么 / 没证明什么”。

## 总体主线

> 具身智能数据合成不是简单增加视频数量，而是围绕视觉、状态、语言、动作、时间五类数据契约，补齐真实数据的覆盖、监督和成本缺口，并最终通过 VLA/WAM 的下游控制效果验收。

## Slide 04｜定义与核心边界

**页面类型**：中心结论 + 两个个边界

**标题**：我们要合成的不是视频，而是能被机器人学习的轨迹

**主张**：围绕视觉、状态、语言、动作、时间五类契约，补足真实数据难覆盖的任务、场景与本体分布。

**两个边界**：

- 视觉可看 ≠ 动作可学
- 数据来源 ≠ 动作监督来源

**讲解补充**：具身数据合成生成的是时序交互过程，不是普通图像增强。

**建议插图**：左侧放“单段视频”示意，右侧放“视觉 + 状态 + 语言 + 动作 + 时间”的完整轨迹示意，中间用“不等于”连接。

## Slide 05｜真实数据与合成数据

**页面类型**：左右对比

**标题**：真实数据最可信，合成数据负责补规模和长尾

**真实数据**：

- 物理与控制分布可信
- 采集、标注和复现成本高
- 危险、罕见和长尾场景覆盖不足

**合成数据**：

- 可控地产生规模与变化
- 可定向覆盖任务与环境组合
- 必须经过动作一致性和下游质量门

**页面结论**：合成数据是对真实数据的补充，不是替代。

**来源**：Open X-Embodiment、MimicGen、Cosmos Predict2。

**建议插图**：左右各放一张真实机器人采集照片与仿真/生成场景图；下方标出“可信度、规模、长尾”。

## Slide 06｜产业链位置

**页面类型**：横向流程图

**标题**：数据合成在链路中间，但最终要回到真机

**流程**：

```text
机器人/仿真器
  → 采集与遥操作
  → 清洗/格式化
  → 数据合成与扩充
  → VLA/世界模型训练
  → 仿真与真机验证
```

**页面结论**：数据合成不是一次性的中间步骤，部署失败会反向提出新的采集和合成需求。

**来源**：本地调研综述。

**建议插图**：优先采用“Collect → Train → Evaluate → Deploy → Loop”的机器人训练闭环图；没有可靠图片时画带回流箭头的原生流程图。

## Slide 10｜动作维度与 embodiment

**页面类型**：本体类型对比

**标题**：同样叫 `action`，不同机器人含义并不一样

**机械臂与移动操作**：

- 单臂：末端 6D + gripper，或逐关节控制
- 双臂：左右臂分别建模并保持同步
- 移动操作：机械臂动作 + 底盘速度

**人形与灵巧手**：

- 双臂、躯干、头部、腿部构成高维全身控制
- 灵巧手还包含多指关节或低维手势基元
- 坐标系、控制频率和归一化必须与本体同步

**页面结论**：手指、腿、腰和头是否进入 action，取决于任务与控制器；有些部件只作为 state 输入。

**建议插图**：使用单臂、双臂、人形、移动操作四个机器人轮廓，在对应部件旁标出动作维度。

## Slide 16｜方法 A-1：仿真与专家轨迹

**页面类型**：方案 / 边界左右对比

**标题**：仿真能同时生成画面、状态和动作

**方案**：Isaac Sim、MuJoCo、SAPIEN、RoboSuite、LIBERO；脚本、规划器或专家策略产生轨迹；域随机化扩大场景覆盖。

**优势**：动作监督可靠、规模化容易、状态完整。

**风险**：接触、材质、传感器和动力学存在 sim2real gap。

**验收**：仿真成功率、碰撞率、轨迹可执行性、真机迁移成功率。

**讲解方式**：先用一句话解释“模拟器知道机器人每个关节在哪里”，再讲 sim2real gap；不要一上来罗列仿真器名称。

**素材位**：优先放置仿真器中的“场景随机化 → 专家 rollout → 轨迹导出”截图或官方流程图；如果没有合适图片，使用原生三步流程图，不让低清论文截图占据主视觉。

## Slide 18｜补充数据源：人类视频参与机器人学习

**页面类型**：转换路径 / 风险左右对比

**标题**：人类视频能教任务，但不能直接教机器人怎么动

**转换路径**：手部/人体姿态估计、对象跟踪、3D 重建、接触推断、机器人 retargeting、语言步骤补全。

**风险**：视角和遮挡导致动作歧义；人体动作与机器人控制空间不等价；必须做仿真或真机可执行性检查。

**动作监督来源**：姿态估计、优化和机器人回放，不是原始视频直接提供。

**建议插图**：三帧故事图：人类演示 → 手部/人体关键点 → 机器人回放；中间标注“需要 retargeting”。

# 生成 PPT 时的统一约束

1. 每页只保留一个主张，标题使用结论句，不使用内部工作口径。
2. Part 1–2 控制在科普密度；Part 3 统一用“输入—模型—输出—动作来源—优势—风险—评价”解释方法；Part 4 明确区分已验证与待验证。
3. 图片只作为证据或解释，不让图片替代链路文字；宽图使用全宽布局，不能缩成不可读的小图。
4. DreamGen + IDM 的动作是伪动作；Cosmos Action-Conditioned Bridge 的动作来自真实 annotation；两者不能混称。
5. GR00T loss 下降只证明训练过程可持续，不作为策略收益结论。
6. 需要新增实验结果时，优先放在 Slide 31–35 的留白区域，不破坏前面的方法框架。

# 总结口径

> 具身智能数据合成的核心不是生成更多视频，而是在统一的数据契约下，补齐真实数据难覆盖的任务、场景、本体和动作监督，并通过可执行性、训练加载和下游控制收益逐层验收。

当前实测已经证明两类链路可以运行：

- DreamGen → IDM → LeRobot → GR00T：视频生成后由 IDM 补伪动作，再进入 VLA 训练；
- Bridge 首帧 + 真实 action → Cosmos Action-Conditioned：动作来自真实轨迹，Cosmos 生成对应视觉未来。

当前尚未证明：合成轨迹优于真实或仿真数据，或已经带来 GR00T/WAM/真机成功率提升。这些结论必须由后续 rollout 和对照实验给出。
